# Typa（タイパ）

**小学生が Chromebook で使う、タイピング学習アプリ。**
ローマ字入力の基礎から、コピー・貼り付けなどのショートカットまでを、
「どのキーを どの指で 押すか」を見ながら練習できます。

学習の記録は **学習ログ共通スキーマ `study.v1`** で保存され、
[まなびクエスト](https://github.com/GIGAyama/Gamification) の「タイピング記録」に
**自動で記録されます**（児童が数値を手で入力することはありません）。

```
https://gigayama.github.io/Typa/
```

## このアプリが大事にしていること

### 1. 「どの指で押すか」がいつも見えている

タイピングが速くならないいちばんの原因は、**人差し指2本だけで打つ癖**です。
一度ついた癖は、あとから直すほうがずっと大変です。

そこで Typa は、次に押すキーを表示するだけでなく、
**そのキーを担当する指**を、画面のキーボードの色・キーの縁取り・
そして「みぎの ひとさしゆびで」ということばの3つで同時に伝えます。
色が見分けにくい児童でも、ことばと形で分かります。

打ち間違えても先へは進みません。正しい指で打ち直すところまでが1打です。

### 2. 学校の Chromebook と同じキーボードを出す

画面のキーボードは、**日本語配列（JIS）の Chromebook** をそのまま写しています。

- Enter は縦2段のかぎ形（JIS のかたち）
- Caps Lock の位置にあるのは **けんさくキー**
- いちばん上の列は、ファンクションキーではなく **ブラウザの操作キー**（もどる・すすむ・ぜんがめん…）
- スペースの左右に **英数 / かな**
- `F` と `J` のでっぱりを画面でも表現

手もとと画面が同じ形なので、視線を往復させても迷いません。
外づけキーボードなどのために、英語配列（US）にも切り替えられます。

### 3. 楽しいけれど、気が散らない

ゲームらしさは「色・形・ほんの少しの動き」だけで作り、
キラキラした装飾・絵文字・にぎやかな背景は置いていません。
**画面の中でいちばん目立つのは、いつもお題の文字**です。

- アイコンはすべて自前の SVG（絵文字を使わない）
- アイコンには必ずことばのラベルを添える
- 文字は UD フォントを優先、行間広め、「文字を大きくする」設定あり
- ライト／ダークの両方に対応
- 「動きを減らす」設定の端末ではアニメーションを止める
- タップできるところは 44px 以上

### 4. ローマ字は「習ったやり方」でそのまま打てる

ローマ字には正解が複数あります。学年や教科書で習うやり方も違います。

| かな | 受け付ける打ち方 |
|---|---|
| し | `si` `shi` `ci` |
| じゃ | `zya` `ja` `jya` |
| ちょ | `tyo` `cho` `cyo` |
| ふ | `hu` `fu` |
| っ | 次の子音を2回（`kitte`）／ `xtu` `ltu` `xtsu` `ltsu` |
| ん | `nn` `n'` `xn`／次が子音なら `n` 1回（`kanji`） |

ヒントには**いちばん基本の打ち方**だけを出すので、画面は迷いません。

> **語尾の「ん」は `nn` が必要です。**
> これは意地悪ではなく、本物の IME と同じ動きです。
> `nihon` と打つと IME では「にほn」のままになってしまうため、
> 「ん は n を2回」を最初から正しい習慣として身につけます。
> 専用のステージ（ローマ字 → 「ん の うちかた」）も用意しています。

### 5. ショートカットは「おぼえる」ではなく「やってみる」

ショートカットのステージには、本物の入力欄が2つあります。
児童は実際に **選んで・コピーして・貼り付けて・元に戻します**。
合格の判定は「キーを押したか」ではなく、**やった結果が正しいか**です。

ブラウザの機能が先に動いてしまうキー（`Ctrl+S` 保存・`Ctrl+F` 検索など）だけは、
ページ側で止めてキーの組み合わせを見ています。

## 画面の構成と「もどる」操作

```
ホーム
れんしゅう ─ コース ─ ステージ（練習中）─ けっか
きろく
せってい
```

画面の下にナビゲーションバーがあり、**いちばん左が「もどる」**です。
「もどる」は次の3つがすべて**同じ1つの動き**になります。

1. 下部バーの「もどる」をタップ
2. **画面の左右どちらかの端から中央へスワイプ**（引いた量が画面の端に見えます）
3. 端末・ブラウザの戻る（Android の戻るジェスチャー、iOS の端スワイプ、Alt+←）

### アプリが終了したり、ブラウザだけ先に戻ったりしません

ブラウザの戻るは、ふつうに使うと**アプリから出てしまいます**。
Typa は起動時に「見えない履歴」を1つ足しておき、戻られたらすぐ足し直します
（`js/nav.js` の `armGuard`）。こうすることで、

- 戻る操作は**いつもアプリの中で受け取られます**
- 階層のいちばん上で戻っても、**ページから出ません**（画面が少し揺れて知らせます）
- バーのタップと端末の戻るが二重に届いても、**0.4秒以内は1回の操作**として扱います

練習中に「もどる」を押したときは、1回目は「もう1かい おすと やめます」と表示して
とどまります。うっかり触って消えてしまうのを防ぐためです。

## どの端末でも本文が広い

- 幅の狭い画面では**上のバーを出さず**、下部バーだけにしています
- iPhone のホームバー・ノッチは `env(safe-area-inset-*)` でよけます
- お題の文字は `clamp()` で画面幅に合わせて拡大（大画面では 3.2rem）
- 画面のキーボードは横スクロールできるので、狭い画面でも本文が押しつぶされません
- **キーボードのない端末**（タブレット・スマートフォン）では、
  画面のキーをタップして打てます（シフトは押すたびに切り替わります）

## PWA（アプリとしてインストール）

`manifest.webmanifest` と `sw.js` で PWA に対応しています。

| ブラウザ | 入れかた |
|---|---|
| **Chrome / Edge**（Chromebook・Windows・Android） | アドレスバー右のインストール、またはメニュー →「アプリをインストール」。アプリ内の「せってい → アプリとして つかう」からも入れられます |
| **Safari**（iPad・iPhone・Mac） | 共有ボタン →「ホーム画面に追加」 |

インストールするとブラウザのバーが消え、画面がさらに広くなります。
**オフラインでも練習できます**（学校の Wi-Fi が混んでいても授業が止まりません）。

Service Worker のスコープは `/Typa/` だけなので、同じ `gigayama.github.io` にある
ほかの学習アプリやまなびクエストの学習ポータル（`/Gamification/`）には影響しません。

## 学習データ（study.v1）

Typa は**通信をしません**。練習1回ぶんのきろくを、同一オリジンの
`localStorage`（キー `study.records.v1`）にためるだけです（仕様 §0-2 / §1）。

```
Typa（gigayama.github.io/Typa/）
  └ localStorage: study.records.v1 に追記
       └ 学習ポータル（gigayama.github.io/Gamification/manabi-portal/）が読み出して送信
            └ まなびクエスト（GAS）→「学習ログ」＋「タイピング記録」シート
```

児童の名前も出席番号も持ちません。誰のきろくかは、
**まなびクエストにログインしているアカウント**から決まります。

### レコードの中身

| 項目 | 入る値 |
|---|---|
| `appId` | `typa` |
| `kind` | `set`（お題が決まっているひとまとまり） |
| `mode` | `key` / `romaji` / `word` / `sentence` / `shortcut` |
| `unit.id` / `unit.title` | ステージID / 「コース名／ステージ名」 |
| `unit.grade` | 想定学年（1〜6） |
| `elapsedMs` | 最初から最後まで |
| `activeMs` | **5秒より長い手止まりを除いた時間**（仕様 §2.8） |
| `source` | `course`（順番どおり）/ `review`（もう1かい） |
| `grading` | `objective`（アプリが正誤を判定） |
| `summary.count` | **お題の数**（打鍵数ではありません） |
| `summary.firstTryCorrect` | **一度もミスせずに打てたお題の数**（主指標。仕様 §2.7） |
| `items[]` | お題ごとの `q` / `ok` / `firstTry` / `tries` / `ms` / `wrong`（打ち間違えたキー）/ `skill` |

打鍵数はお題の数と単位が違うため、**拡張層 `ext`** に入れています。

| `ext` | 入る値 |
|---|---|
| `correctKeys` | 正しく打てた打鍵数 |
| `totalKeys` | 打った合計数（ミスを含む） |
| `missKeys` | 打ち間違えた数 |
| `kps` | 速さ（打/秒）＝ `correctKeys ÷ activeMs の秒数` |
| `accuracy` | 正答率（%）＝ `correctKeys ÷ totalKeys` |
| `layout` | `jis` / `us` |
| `courseId` / `stageId` | どの練習か |
| `missByKey` | ミスの多かったキー（上位10） |
| `missByFinger` | **指ごとのミス回数**（上位10） |
| `itemsTruncated` | お題が200件を超えたときの本当の解答数（仕様 §2.7） |

> **速さは「正しく打てた数 ÷ 秒」です。**
> 打ち間違えは速さに入りません。合計打鍵数で数えると、
> でたらめに連打したほうが記録が伸びてしまい、ランキングが壊れるためです。

`skill`（ステージごとのラベル）と `missByFinger` があるので、先生の画面では
**「クラスのどの指づかい・どの段がにがてか」**まで見ることができます。

### 端末に残るもの

| キー | 中身 | 消える？ |
|---|---|---|
| `study.records.v1` | まなびクエストへ送る学習ログ（全アプリ共通） | 送信後にポータルが削除 |
| `typa.history.v1` | Typa 自身の練習履歴（最新300件） | 残ります |
| `typa.progress.v1` | ステージごとの★・最高記録 | 残ります |
| `typa.settings.v1` | 配列・表示・音などの設定 | 残ります |

学習ログは送信すると消えるので、**児童の手もとに歩みが残るように
Typa 自身の履歴を別に持っています**（「きろく」タブ）。

## コースとステージ

| コース | ねらい | ステージ数 |
|---|---|---|
| **ゆびの ばしょを おぼえる** | ホームポジションから段を広げる（アルファベット直打ち） | 7 |
| **ローマ字を おぼえる** | あ行〜わ行・濁音・ん・っ・拗音 | 11 |
| **ことばを 打つ** | 身のまわり／学校／学習／コンピュータ／地名のことば | 5 |
| **文を 打つ** | あいさつ・日記・ふり返り・長い文（句読点つき） | 4 |
| **ショートカットを つかう** | コピー・貼り付け・元に戻す・選択と移動・便利なキー | 4 |

★は**速さではなく正確さ**で決まります（98%以上で★3）。
速さで決めると「間違えても速く打つほどよい」という誤った練習になるためです。

内容は `js/lessons.js` にまとまっているので、学級の実態に合わせて
ことばや文を差し替えられます。

## ファイル構成

```
Typa/
├── index.html                アプリの外枠（下部ナビゲーションバー）
├── manifest.webmanifest      PWA の設定
├── sw.js                     オフライン対応（スコープは /Typa/ だけ）
├── css/style.css             デザイントークンと全画面のスタイル
├── icons/                    アイコン（make_icons.py で生成）
└── js/
    ├── icons.js              自前の SVG アイコン
    ├── layout.js             JIS / US のキー配列と「どの指で押すか」
    ├── romaji.js             ローマ字入力エンジン（複数の打ち方を受理）
    ├── lessons.js            コース・ステージ・ショートカット課題
    ├── store.js              設定・すすみぐあい・練習履歴
    ├── studylog.js           study.v1 の書き出し
    ├── keyboard.js           画面のキーボード
    ├── nav.js                画面の階層と「もどる」（履歴ガード・端スワイプ）
    ├── play.js               打つ練習の画面
    ├── shortcut.js           ショートカットの練習画面
    └── app.js                各画面の中身と起動
```

外部のライブラリ・フォント・CDN は使っていません（オフラインで完結します）。

アイコンを作り直すときは次を実行します（追加のインストールは不要です）。

```bash
python3 icons/make_icons.py
```

## 公開のしかた（GitHub Pages）

1. このリポジトリの **Settings → Pages** で、Source を `Deploy from a branch`、
   ブランチを `main` / `(root)` にする
2. `https://gigayama.github.io/Typa/` が開くことを確認する
3. **まなびクエスト側で受信の準備をする**（下の節）

> 学習ログは**同一オリジンの `localStorage`** でやりとりするため、
> Typa は学習ポータルと同じ `gigayama.github.io` にある必要があります。
> オリジンはスキーム＋ホスト＋ポートで決まり**パスは関係しない**ので、
> このリポジトリを GitHub Pages で公開するだけで条件を満たします。

### まなびクエスト側の準備（先に行ってください）

仕様 §9.4 のとおり、**アプリの公開より先に受信側を更新します**。

1. `manabi-quest/10_studylog.gs` の `STUDY_APPS` に `typa` があることを確認する
2. GAS のスクリプトを反映し、メニュー「① 初期セットアップ」を再実行する
3. **デプロイを更新（新しいバージョン）**する
4. 実機で1件送信し、「学習ログ」と「タイピング記録」の両方に行が増えることを確認する

受信側が未対応のままだと、レコードは一時エラーとして**児童の端末に残り続けます**
（消えはしませんが、ポータルの未送信件数が減りません）。

## 児童の使いかた

1. Typa を開いて、コース → ステージを選んで練習する
2. 練習が終わると、この端末にきろくがたまる
3. **学習ポータル**（まなびクエスト）を開くと、たまったきろくが自動で送られる
4. まなびクエストで経験値・ミッション・ランキングに反映される

ホームと「せってい」に、未送信の件数と学習ポータルへのボタンを出しています。

## 先生へ：うまくいかないとき

| こまりごと | 見るところ |
|---|---|
| 打ってもキーが反応しない | 画面に「かな入力に なって いるみたい」と出ていませんか。**英数キー**（スペースの左）を押します |
| 画面のキーボードと手もとの形が違う | せってい →「キーボードの ならび」を US に変えます |
| 未送信の件数が減らない | まなびクエスト側の `STUDY_APPS` に `typa` があるか、デプロイを更新したかを確認します |
| きろくが保存できないと出る | ブラウザのシークレットモード／保存領域の制限を確認します |
| 色が見分けにくい | 指の名前が必ずことばでも出ます。せってい →「指を 色で 分ける」を切ると、次のキーの強調だけになります |

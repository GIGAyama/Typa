# note 入稿メモ（Typa 紹介記事）

連載「教室で使えるかもしれないもの作り」に載せる Typa の紹介記事一式です。

```
docs/note/
├── typa-note-article.md   記事本文。そのまま note に貼れる形
├── images/                実際に操作して撮った画面 25点
└── README.md              このファイル
```

---

## 1. 貼るまえに、ここだけ直してください

**連載番号が `#◯` のままです。** 見出し行の

```
# 教室で使えるかもしれないもの作り #◯ 名簿もログインもなし。…
```

の `#◯` を正しい番号に置きかえてください。推測で埋めると連載が壊れるので、
こちらでは入れていません。

タイトルの後半は入れかえていただいてかまいません。連載の型
（「困っていること」＋持ち味＋アプリ名）にはそろえてあります。

---

## 2. note に貼る手順

1. note で新しい記事を作り、1行目のタイトル欄に見出しの `# ` を除いた本文を貼ります。
2. `typa-note-article.md` の `## 🏫 はじめに` 以降を本文欄に貼ります。
   見出しの `##` は note のエディタで見出しとして認識されます。
   note は見出しから目次を自動で作るので、見出しの並びが記事の骨格になります。
3. **画像は手でアップロードします。** 本文の `![…](images/xx.png)` の行を消して、
   その位置に `images/` の同じ番号の PNG をアップロードしてください。
   下の対応表のとおりに並べれば、本文の流れと合います。
4. 画像の直後の一文は、note の**キャプション欄**に移してください。
   本文に残すと浮きます。
5. ハッシュタグの候補。`#GIGAスクール` `#タイピング` `#小学校` `#ICT教育`
   `#Chromebook` `#ローマ字入力` `#情報活用能力`

画像はすべて横 2560px（2倍で撮影）です。note にそのまま上げて問題ありません。
`04` `05` `15` `18` `25` はたてに長い画面なので、note では小さく見えます。
気になる場合は、その5点だけ「大きいサイズ」で配置してください。

## 5. 撮影について

### 壊れている機能は見つかりませんでした

25点すべて、実際に操作して撮っています。撮影中にブラウザのコンソールに出た
エラーは0件で、押せなかったボタンもありませんでした。
記事の公開前に直していただく修正はありません。

★3つでの自動入れかわり、ショートカットのコピーと貼り付け、
30秒チャレンジ、にがて とっくん、記録の書き出し画面まで、
記事で紹介した機能は全部この撮影で踏んでいます。

### 撮り直すときの手順

撮影用のスクリプトはリポジトリに残していません（納品前に消しました）。
撮り直すときは次の手順で再現できます。

```bash
npm i --no-save playwright

# Typa はビルドが要りません。リポジトリのルートをそのまま配ります。
# 第3引数のベースパス /Typa/ を省かないでください。
# Service Worker と manifest が /Typa/ という絶対パスを持っているためです。
node <skill>/scripts/serve.mjs . 4180 /Typa/

# べつのターミナルで
node <skill>/scripts/capture.mjs shots.mjs --base http://127.0.0.1:4180/Typa/ --out shots
```

`shots.mjs` を書くときに踏んだところを残しておきます。

- **画面の大きさは 1280 × 920 が合います。** Chromebook を想定した横長です。
  920 より低いと、キーボードの下の手の絵が切れます。
- **たてに長い画面は、撮る前にビューポートを伸ばします。** けっか画面ときろくと
  せっていは 920 に収まりません。`document.documentElement.scrollHeight` を測って
  その高さにリサイズしてから撮ると、切れも余白も出ません。
- **打つのは本物のキー入力です。** `#play-finger b` に「つぎは D を」の D が
  入っているので、それを読んで `keyboard.press()` します。アプリは `e.key` で
  判定しているので、コード名ではなく文字を押します。
- **一定の間かくで打たないでください。** けっか画面の「どこで手がとまったか」の
  棒グラフがまっ平らになります。120〜300ミリ秒でゆらして、ときどき長めに止めると
  実際の画面になります。
- **わざと数問まちがえます。** 全問正解だと、にがてのヒートマップも
  にがて とっくんも空のままで撮れません。
- **★3つになると自動で次のステージに入れかわります。** けっか画面を撮りたいときは
  先にまちがえておくか、「やめる」を押して出します。

## 6. 文体について

`references/style.md` の連載ルールに合わせてあります。守ったのは次のところです。

- 太字（`**`）、斜体、表、`→` `／` `：` `▲` `▶` は本文に1つも使っていません
  （機械的に数えて0件を確認しました）
- 箇条書きは導入手順と使い方のガイドだけです。ほかは文章で書いています
- 見出しは連載の基本形に、目玉が収まらなかったぶんを2本足しました。
  📱 と ✨ のあいだに「🎹 どのゆびで押すか」と「🔎 つまずいたところ」です
- 絵文字は見出しだけです
- 専門用語は日常の言葉に置きかえました。ローカルストレージは「その端末の中だけ」、
  PWA は「アプリとして入れる」、LCP は「画面が出るまで」と書いています
- 本文は約7,500字です

書いていないこともあります。

- **教室での出来事は書いていません。** これは作者の実践記録ではないので、
  「使ってみたら子どもたちが」とは書けません。「こうなればいいと思って作った」
  までにしてあります。実際の授業での様子は、ここに足していただくところです
- **効果は言い切っていません。** 「〜だと思います」「〜のではないかと思っています」
  でとめています
- 前作との地続きは作っていません。連載のどの回とつなげるかが分からなかったためです。
  つなげたい記事があれば、🏫 はじめに の終わりに一段落足すのが収まりがよいです
